# NPL Portfolio Cash Flow Forecast and Variance Analysis

Даний проєкт присвячений аналізу, оцінці якості прогнозування та виявленню причин відхилень фактичного платіжного потоку (Cash Flow) від прогнозованого за портфелем простроченої заборгованості (Non-Performing Loans, NPL).

---

#1. Бізнес-контекст та цілі проєкту

При придбанні портфелів прострочених кредитів фінансова компанія будує розрахункову модель майбутніх грошових надходжень для оцінки окупності інвестицій (ROI) та управління ліквідністю. На практиці фактичні касові надходження відхиляються від планових показників під впливом макроекономічних чинників, сезонності та деградації якості боргу.

Ключові аналітичні задачі:
1. Кількісна оцінка відхилення фактичних виплат від прогнозованих у часовій динаміці та у розрізі продуктових сегментів.
2. Розрахунок кривих накопичуваного коефіцієнта повернення боргу (Cumulative Recovery Rate) за NPL-когортами.
3. Ідентифікація системних факторів похибки прогнозування (сезонні провали, макроекономічні індикатори, сегментні особливості).
4. Формування рекомендацій для коригування алгоритмів прогнозування та операційної стратегії стягнення.

#2. Технологічний стек

* Мова програмування: Python 3.9+ (бібліотеки Pandas, NumPy, Requests, Matplotlib, Seaborn, OpenPyXL).
* База даних: SQL / SQLite (DDL-проектування, агрегаційні запити, когортний аналіз, віконні функції OVER/PARTITION BY).
* Інтеграція даних: REST API Національного банку України (автоматичне завантаження макроекономічних показників).
* Звітність: Microsoft Excel (багатосторінковий консолідований звіт для бізнес-користувачів).

#3. Архітектура та схема бази даних (SQLite)

Збереження та обробка даних реалізовані в реляційній базі даних `npl_analytics.db` з явним визначенням первинних (Primary Key) та зовнішніх (Foreign Key) ключів.



#Опис таблиць
* `portfolio`: Реєстр кредитної заборгованості (1 000 угод). Містить дані про суму основного боргу, дату виходу в NPL, регіон та продуктовий сегмент (*Consumer_Micro*, *Cash_Loan*, *Auto_Legacy*).
* `payments`: Транзакційний журнал щомісячних платежів із сопоставленням планового (`forecast_payment`) та фактичного (`actual_payment`) показників.
* `macro`: Довідник щомісячних макроекономічних індикаторів (офіційний курс USD НБУ, облікова ставка, інфляція YoY).

*Примітка щодо походження даних:* Проєкт використовує гібридну модель даних. Макроекономічні показники імпортовані через офіційний API НБУ. Параметри портфеля кредитів та транзакційний потік згенеровані моделюючим алгоритмом на Python із збереженням галузевих закономірностей (сезонні коливання, розпад платіжної активності з часом).

#4. Методологія та етапи реалізації

#Етап 1. Контроль якості даних (Data Quality Assurance)
* Перевірка цілісності: контроль відсутності пропущених значень (NULL) та дублікатів первинних ключів.
* Статистичний аналіз аномалій: розрахунок Z-score для транзакційних виплат ($Z = \frac{X - \mu}{\sigma}$). Записи з $\vert{}Z\vert{} > 3$ виділено для окремого аналізу статистичних викидів.

#Етап 2. Когортний аналіз та SQL-аналітика
* Групування угод за місяцем виходу у прострочення (`cohort_month`).
* Розрахунок накопичуваного касового потоку за допомогою віконних функцій SQL:
  `SUM(monthly_actual) OVER (PARTITION BY cohort_month ORDER BY payment_month)`
* Розрахунок накопичувального Recovery Rate:
  $$\text{Cumulative Recovery Rate} = \frac{\sum \text{Actual Payments}}{\text{Total Principal}} \times 100\%$$

#Етап 3. Оцінка точності прогнозування
* Розрахунок метрик похибки моделі: MAE, RMSE, MAPE, WAPE.
* Оцінка кореляції Пірсона між абсолютним відхиленням прогнозу ($Actual - Forecast$) та динамікою курсу USD.

#6. Висновки та бізнес-рекомендації (Executive Summary)

#Результати аналізу
1. **Системний сезонний фактор:** Похибка прогнозування в першому кварталі викликана відсутністю в базовій моделі сезонних коефіцієнтів падіння платіжної дисципліни боржників у січні (відхилення від плану становить ~25-30%).
2. **Сегментна волатильність:** Продукт *Consumer_Micro* демонструє найбільшу дисперсію виплат у літній період (червень–серпень). Портфелі *Cash_Loan* та *Auto_Legacy* показують високу прогнозованість та відповідність плановим метрикам.
3. **Еластичність до макропоказників:** Коливання валютного курсу чинять опосередкований негативний вплив на коефіцієнт повернення у сегменті необеспеченого споживчого кредитування.

#Рекомендації для впровадження
* **Модифікація прогнозної моделі:** Впровадити в алгоритм розрахунку Cash Flow сезонні коригуючі коефіцієнти ($k_{01} = 0.75$ для січня; $k_{07-08} = 0.80$ для липня-серпня у сегменті *Consumer_Micro*).
* **Оптимізація стратегії стягнення:** Перерозподілити операційні ресурси контакт-центру на роботу з когортами віком DPD 1–90, де швидкість зростання Cumulative Recovery Rate є максимальною.
* **Реструктуризація застарілого боргу:** Для когорт віком понад 180 днів DPD пропонувати програми дисконтування заборгованості, оскільки щомісячний приростовий Recovery Rate після 6-го місяця падає нижче 0.5%.
